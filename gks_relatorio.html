Relatório — Gerenciador de Memória Virtual

Disciplina: Sistemas Operacionais
Projeto: Designing a Virtual Memory Manager
Referência: Silberschatz, Operating System Concepts, 10ª ed.
Data de entrega: 03/06/2026
Aluno(a): GKS

1. Objetivo

Implementar um simulador de gerência de memória virtual em linguagem C, capaz de traduzir endereços lógicos de 16 bits em endereços físicos utilizando TLB (Translation Lookaside Buffer), tabela de páginas e armazenamento de backup (backing store). O programa suporta dois algoritmos de substituição — FIFO e LRU — tanto para páginas quanto para entradas da TLB, além de realizar a busca na TLB com uma thread POSIX por entrada.

5. Fluxo de Tradução de Endereços

Para cada endereço lógico lido do arquivo de entrada:

  1. Extrair número de página: page = (addr >> 8) & 0xFF
  2. Extrair offset: offset = addr & 0xFF
  3. Consultar a TLB via threads (uma thread por entrada)
  4. Se TLB miss → consultar a tabela de páginas
  5. Se page fault → ler 256 bytes do BACKING_STORE.bin
  6. Atualizar memória física, tabela de páginas e TLB
  7. Calcular endereço físico: (frame << 8) | offset
  8. Retornar o valor armazenado (byte com sinal)

6. Algoritmos Implementados

6.1 FIFO — Substituição de Páginas

Os 128 frames são preenchidos em ordem (0 → 127). Quando todos estão ocupados, um ponteiro circular identifica o frame carregado há mais tempo e o substitui. A cada evicção, o ponteiro avança: fifo_fptr = (fifo_fptr + 1) % NUM_FRAMES.

6.2 LRU — Substituição de Páginas

Cada frame mantém um timestamp de último acesso (frame_used) atualizado a cada leitura. Na substituição, percorre-se os 128 frames e elege-se o de menor timestamp como vítima.

6.3 FIFO — Substituição de TLB

Cada entrada da TLB possui um campo inserted (clock no momento da inserção). A substituição escolhe sempre a entrada com menor inserted, garantindo comportamento FIFO correto mesmo após invalidações pontuais de entradas.

6.4 LRU — Substituição de TLB

Cada entrada possui um campo accessed atualizado em todo TLB hit. A substituição elege a entrada com menor accessed.

7. Threads — Busca na TLB

A cada tradução de endereço são criadas 16 threads POSIX (uma por entrada da TLB). Cada thread verifica exclusivamente sua entrada; a primeira a encontrar correspondência registra o resultado em uma variável compartilhada protegida por pthread_mutex_t. O fluxo principal aguarda todas as threads com pthread_join antes de continuar. 

for (i = 0; i < TLB_SIZE; i++)
    pthread_create(&tids[i], NULL, tlb_search_fn, &args[i]);

for (i = 0; i < TLB_SIZE; i++)
    pthread_join(tids[i], NULL);

11. Dificuldades Encontradas

  • FIFO da TLB com invalidações: a abordagem inicial com ponteiro circular gerava evicções incorretas quando uma entrada era invalidada (por evicção de página) e depois reinserida. A solução foi substituir o ponteiro por timestamps de inserção (inserted), garantindo sempre a evicção da entrada mais antiga.
  • Sincronização das threads: sem o mutex, duas threads podiam escrever simultaneamente na variável de resultado, causando condição de corrida. A adição de pthread_mutex_lock/pthread_mutex_unlock resolveu o problema, confirmado com ThreadSanitizer.
  • Invalidação cruzada TLB–Page Table: ao evictar um frame, era necessário invalidar tanto a entrada da tabela de páginas quanto a entrada correspondente na TLB; esquecer um dos dois gerava traduções incorretas para a página evictada.

12. Conclusão

O projeto foi implementado integralmente em C, seguindo todos os requisitos do enunciado: memória física de 128 frames, TLB de 16 entradas, algoritmos FIFO e LRU para substituição de páginas e de TLB, e busca na TLB realizada via threads POSIX. O código compila sem warnings com -Wall -Wextra -Wpedantic e não apresenta memory leaks nem race conditions.
